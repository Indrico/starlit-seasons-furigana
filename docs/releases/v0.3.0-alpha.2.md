# v0.3.0-alpha.2 - Preserve native menu-guide layout

This fixes the menu layout reported after alpha.1. Adding furigana enlarged the
bottom-right gray background and shifted the Enter/Esc guides. Ruby overlays now
follow native geometry without contributing to the native panel's desired size.
The guide background and buttons retain their original dimensions and positions
when annotations appear or are toggled. Main fonts and furigana sizes are unchanged.

Names, menus, backlog, manual/automatic dialogue, the Options master switch, and
startup-logo skipping remain available.

## Installation

Download `starlit-season-furigana-v0.3.0-alpha.2-windows-x64.zip`.
Close the game, uninstall the previous managed version, and extract all ZIP
contents next to `StarlitSeason.exe`. Run `Check-Furigana.cmd`, then launch
through Steam. No build tools, Python, or separate loader download are needed.
Preferences survive uninstalling and upgrading. See the [English usage guide](../usage.md).

- **F6:** manual/automatic dialogue.
- **F7:** furigana off/on.
- **OPTION > Furigana Mod: ON/OFF**, or **F8** in that menu: every mod feature.

The supported target remains Windows x64, game 1.61 / Steam build 8278842.

## Verification and limits

The regression checks cover padded overlays at multiple scales without growing
the native canvas's desired size. The full source suites contain 127 tests.
In-game checks used a 1920 x 1080 client and compared the Album help banner and
Enter/Esc panel with F7 off/on. Options System scrolling retained its clipping.
Haruka's Album header, dialogue name, and short backlog retained their readings.
The exact ZIP passed removal/reinstallation with all 26 runtime hashes checked,
both known English-patch files restored identically, and preferences preserved.
See [runtime verification](../runtime.md) for the sampled scope.

This is a layout correction. Frame-time benchmarks were not repeated for this
update; unexplained stuttering recorded for alpha.1 remains an open follow-up.
Automatic readings, cold UI preparation, unsupported labels/styles, and untested
screens/controller paths retain the limitations described in the
[UI notes](../ui-annotations.md) and [performance evidence](../performance.md).
