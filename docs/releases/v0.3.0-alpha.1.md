# v0.3.0-alpha.1 — Names, menus, and backlog

This prerelease extends Japanese furigana beyond dialogue and choices.

- Character-name labels use exact verified readings, including spaced and short
  aliases. Unknown or ambiguous names retain native rendering.
- Japanese menu labels and help text gain ruby while keeping the original main
  font, widths, alignment, and input. Menu ruby is smaller following player
  feedback; compact captions use a proportional size. Name/log ruby stays larger.
- Dialogue backlog gains name and body readings. Cards can gain height to fit
  ruby, with matching selected/unselected layouts. Native scrolling and voice
  controls remain in place. F7/master Off restores original dimensions.
- Geometry follows nested UI transforms. Existing overlays receive priority
  during scroll/focus changes, and inactive screens skip reading work. Cold
  preparation uses bounded caches and a cooperative game-thread budget.
- The package includes 56,494 exact-source annotation entries, 160 verified
  name aliases, and 99 calibrated name-texture bindings. Assets and original
  base text are excluded; release data stores hashes, spans, kana, and normalized
  coordinates only.

Manual/auto dialogue, fixed dialogue sizes, compact dialogue boxes, the Options
master switch, and startup-logo skipping are retained from v0.2.

## Installation

Download `starlit-season-furigana-v0.3.0-alpha.1-windows-x64.zip`.
Close the game and uninstall an older managed installation first. Extract all
ZIP contents next to `StarlitSeason.exe`, run `Check-Furigana.cmd`, then launch
through Steam. Players do not need Python, a compiler, extraction tools, or a
separate loader. See the [English usage guide](../usage.md).

- **F6:** manual/automatic dialogue.
- **F7:** all furigana off/on, independently of progression mode.
- **OPTION → Furigana Mod: ON/OFF**, or **F8** in that menu: every mod feature.

The supported target remains Windows x64, game 1.61 / Steam build 8278842, with
the same pinned UE4SS loader and executable-hash checks.

## Verification and limits

The source suites contain 126 tests: 81 Lua runtime/layout/lifecycle, 17 reading,
9 extraction, 12 Python installer, and 7 Windows portable-package tests. Synthetic
coverage includes 100 sources, scrolling, 30 disable/reopen cycles, bounded live
renderers, interrupted preparation, native-size restoration, and image geometry.
All 62,508 distinct private source strings were checked against the exact ZIP's
Lua lookup; all 56,494 annotated entries reproduced the reference spans/controls.

The exact package passed installation/removal/reinstallation and identical
English-patch hash restoration. Three 120-second captures of the late candidate
before the final deferred backlog-end adjustment recorded held-dialogue
p99 intervals of 7.197, 7.248, and 7.184 ms. Two runs had no intervals above
33.33 ms, but the second contained nine, with a maximum of 815.323 ms. The cause
was not attributed; occasional stuttering remains a known follow-up. These are
sampled local measurements, not a guaranteed frame rate. See [performance evidence](../performance.md)
and [runtime verification](../runtime.md) for the final in-game scope.

Readings are automatic and may be wrong. Coverage is not linguistic accuracy.
Exact-source misses, substitutions, rich markup/unresolved table-backed styles,
unknown names, unmapped image labels, and unsupported geometry keep native
rendering. Lyrics are excluded. Not every menu/DLC layout, controller input, or
a full playthrough has been verified. New UI keeps native text visible briefly
while geometry and cold annotations become ready; its main font does not shrink.
